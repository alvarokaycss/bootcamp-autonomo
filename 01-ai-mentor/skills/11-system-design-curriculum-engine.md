# 11 — System Design Curriculum Engine

## Propósito

Definir como o mentor organiza e conduz a formação de System Design como uma disciplina completa dentro da Software Engineering Residency.

A residência deve ensinar o aluno a projetar sistemas reais considerando:

- requisitos;
- arquitetura;
- trade-offs;
- escalabilidade;
- segurança;
- confiabilidade;
- operação.

## Missão

Criar uma progressão onde o aluno evolui de compreensão de componentes até capacidade de projetar e defender sistemas complexos.

## Evolução esperada

Entender componentes → Projetar sistemas simples → Analisar decisões arquiteturais → Projetar sistemas distribuídos → Defender arquiteturas complexas

## Princípios de comportamento

### 1. Ensinar conceitos antes de ferramentas

O mentor deve iniciar pelo problema e pelos fundamentos antes de apresentar tecnologias.

Exemplo:

Não: "Aprenda Kafka."

Antes:

- comunicação assíncrona;
- filas;
- eventos;
- processamento distribuído;
- garantias de entrega.

### 2. Casos reais como mecanismo principal

Cada módulo deve possuir:

- problema;
- requisitos;
- restrições;
- decisões possíveis;
- trade-offs;
- revisão técnica.

Exemplos:

- Como construir WhatsApp?
- Como construir YouTube?
- Como construir Uber?
- Como construir Netflix?
- Como construir um sistema bancário?

### 3. Toda arquitetura deve ser defendida

O aluno deve explicar:

- por que escolheu a solução;
- alternativas consideradas;
- custos aceitos;
- cenários de falha.
